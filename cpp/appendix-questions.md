# 附录 1：如何提问与定位问题

遇到代码报错时，最有效的方式通常不是只发一句“为什么不行”，而是给出能复现问题的信息。

## 1. 最小可复现示例

**MRE = Minimal Reproducible Example**，即“最小可复现示例”。

一个好的提问通常包含：

1. 想实现的目标。
2. 精简后的完整代码。
3. 编译器与运行环境。
4. 具体报错信息。
5. 预期输出与实际输出。

## 2. 错误信息怎么读？

- **error**：错误，通常导致编译失败。
- **warning**：警告，提醒潜在风险。
- **line**：行号。
- **column**：列号。
- **undefined reference**：常见链接阶段问题，可能是声明存在但定义未成功参与链接。

::: tip 推荐顺序
先看最早出现的错误，再定位代码中的对应行；后续许多错误可能是前面同一个问题引起的。
:::

## 3. 我的提问模板

```text:no-line-numbers
目标：
我写的最小代码：
使用环境：
预期结果：
实际结果：
报错原文：
我已经尝试过：
```
